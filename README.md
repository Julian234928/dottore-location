# Dottore Location

一个基于 Android 官方 **Mock Location（模拟位置）** 机制的虚拟定位测试工具。

**无需 Root，无需解锁 Bootloader，不修改系统分区，不碰任何系统文件。** 只用 Android 从 6.0 起就内置的开发者调试能力，把坐标写进系统定位管线。

---

## ⚠️ 先读这一节：这个工具只在特定条件下才有效

这不是"装上就能用"的软件。它有三个硬性前提，缺一个都会失效或者位置闪回真实地点。

### 前提一：目标设备**不能插 SIM 卡**

### 前提二：目标设备**必须关闭 Wi-Fi**

### 前提三：目标设备**通过蓝牙共享网络**来上网

### 为什么必须这样？

Mock Location 能改的，只有 Android 定位服务里 `gps`、`network`、`fused` 这三个"提供者"输出的坐标值。它**改不了**下面这些同样能推导出你真实位置的东西：

| 定位通道 | Mock 能否覆盖 | 后果 |
|---|---|---|
| GPS 卫星定位 | ✅ 能 | 正常，显示你设定的坐标 |
| 系统融合定位（fused） | ✅ 能 | 正常 |
| **Wi-Fi 热点指纹** | ❌ 不能 | 开着 Wi-Fi 就会闪回真实位置 |
| **基站 Cell ID** | ❌ 不能 | 插着 SIM 卡就会闪回真实位置 |
| **IP 地址归属地** | ❌ 不能 | 无法伪造 |
| 蓝牙信标 / 传感器 | ❌ 不能 | 无法伪造 |

所以矛盾就在这里：**设备需要联网才能加载地图、登录账号，但只要联网的手段是 Wi-Fi 或 SIM 卡，真实位置就会从另一条通道漏出去。**

**蓝牙共享网络（Bluetooth PAN）是这个矛盾唯一的解法**：

- 它提供完整的互联网访问 → 应用能正常联网
- 它**不启用 Wi-Fi 射频** → 系统拿不到 Wi-Fi 扫描列表，没有热点指纹可用
- 目标设备**没有 SIM 卡** → 没有基站 ID 可用

于是系统定位管线里，唯一还有数据可用的就只剩你注入的那个 mock provider。位置才稳得住。

> 这个结论不是猜的。开源项目 [ZCShou/GoGoGo](https://github.com/ZCShou/GoGoGo) 的源码注释里明确写着：「开启 WIFI 后（即使没有连接热点）将导致定位闪回真实位置」。

### 推荐的设备组合

| 角色 | 设备 | 要求 |
|---|---|---|
| 目标设备 | 平板 或 备用手机 | **不插 SIM 卡**，装本应用 |
| 网络来源 | 另一台手机 | 有移动数据，开「蓝牙共享网络」 |

两台设备蓝牙配对后，目标设备在「蓝牙 → 已配对设备 → 互联网访问」里连上即可。

## 它能达到什么效果

在满足上面三个前提的情况下：

- **系统级替换**：所有通过 Android 标准定位 API（`LocationManager` / `FusedLocationProviderClient`）取位置的应用，读到的都是你设定的坐标。地图、社交、天气、出行、打卡类应用都在此列
- **数据足够逼真**：补齐了真实 GNSS 定位一定携带的字段——海拔、速度、方向、垂直精度、卫星数量（12 颗）、信噪比（meanCn0 32 / maxCn0 41）。只给经纬度的裸数据一眼就是假的，这套字段是照着真实定位填的
- **分源精度**：GPS 报 8 米、融合定位报 12 米、Wi-Fi 定位报 65 米。三个源报同一个精度是明显的破绽，物理上 Wi-Fi 定位不可能做到 5 米
- **国内坐标直接可用**：从高德/腾讯/百度地图上抄下来的 GCJ-02 坐标，选「GCJ-02」后会自动反算成 WGS84 再注入，不用自己换算
- **持续保持**：前台服务每秒重推一次坐标，切到后台不会掉
- **随时恢复**：点「停止并恢复」，立即回到真实定位
- **可自证**：点「读取系统定位」能直接看到系统当前返回的坐标和 `isMock` 标记，确认注入是否真的生效

## 它做不到什么

请务必看清这一节，避免装完发现"没用"。

- **骗不过服务端交叉校验**。有些应用会把位置上报服务器，再和你的 IP 归属地、Wi-Fi 列表、历史轨迹比对。这类校验发生在服务器上，客户端改不了
- **`isMock` 标记仍然是 true**。Android 8.0+ 起，任何应用都能用 `Location.isMock()` 检查这个位置是不是模拟的。本工具没有、也无法隐藏这个标记
- **重启后不会自动恢复**。Android 14 起系统限制，重启后必须重新打开应用点一次「应用位置」
- **应用被杀就中断**。省电策略、手动清理后台都会让推送停下。请把本应用加入电池优化白名单
- **需要你手动授权**。必须在「开发者选项 → 选择模拟位置信息应用」里选中本应用，应用自己无法代劳
- **海拔是固定值**（780 米）。如果你设定的地点在沿海或高原，海拔会和地形对不上
- **个别 ROM 保护系统级 provider**。部分厂商 ROM 会拒绝接管 `fused`，此时走融合定位的应用可能拿不到数据

## 安装

### 方式一：直接下载 APK

从本仓库的 [`apk/`](apk/) 目录下载 `DottoreLocation-0.4.2.apk`，传到手机上安装。

首次安装需要允许「安装未知来源应用」。

### 方式二：自己编译

```bash
git clone https://github.com/Julian234928/dottore-location.git
cd dottore-location
# 修改 local.properties，指向你自己的 Android SDK
echo "sdk.dir=/path/to/Android/Sdk" > local.properties
./gradlew assembleDebug
```

产物在 `app/build/outputs/apk/debug/app-debug.apk`。

环境要求：JDK 17、Android SDK Platform 35、Gradle 8.13（wrapper 已自带）。

## 使用步骤

### 第一步：准备好网络环境

1. 目标设备**取出 SIM 卡**
2. 目标设备**关闭 Wi-Fi**
3. 另一台手机打开「设置 → 连接与共享 → 蓝牙共享网络」
4. 两台设备蓝牙配对，目标设备连接该蓝牙网络
5. 在目标设备上打开浏览器，确认能正常上网

> 这一步没做对，后面全部白费。位置会一直闪回真实地点。

### 第二步：开启开发者选项

1. 打开「设置 → 关于手机」
2. 连续点击「版本号」7 次，直到提示"已进入开发者模式"
3. 返回「设置 → 系统 → 开发者选项」

### 第三步：授权本应用

1. 在开发者选项里找到「**选择模拟位置信息应用**」
2. 选中「Dottore Location」
3. 打开本应用，顶部应显示 `✓ 已获得模拟位置权限`

### 第四步：设定坐标

1. 选择输入坐标系（从国内地图抄的坐标选 GCJ-02，GPS 原始坐标选 WGS84）
2. 填入纬度、经度，建议保留 6 位小数
3. 点「**应用位置**」
4. 点「**读取系统定位**」验证——应该看到你设定的坐标，且 `isMock：true（模拟）`

### 第五步：验证效果

打开地图应用或目标应用，确认显示的是设定位置。

建议把本应用加入电池优化白名单，避免后台被清理。

## 坐标系怎么选

这是最容易出错的一步。

| 你的坐标来自 | 选哪个 | 说明 |
|---|---|---|
| 高德地图、腾讯地图、Google 中国地图 | **GCJ-02** | 国内加密坐标，和真实 GPS 差 300~800 米 |
| 百度地图 | GCJ-02（需先去掉 BD-09 偏移） | 百度用的是 BD-09，比 GCJ-02 又多一层偏移 |
| 手机 GPS 直接读出的原始值 | **WGS84** | 国际标准坐标 |
| 境外地点 | **WGS84** | 中国境外不做偏移 |

选 GCJ-02 时，应用会自动反算成 WGS84 再注入，界面上会显示换算前后的偏移距离。

## 常见问题

**Q：装好了，授权了，但位置没变？**
先检查 Wi-Fi 是否关掉、SIM 卡是否拔出。这两项是 90% 失败的原因。其次确认「读取系统定位」返回的 `isMock` 是不是 `true`。

**Q：位置一开始对，过一会儿跳回真实地点？**
典型的位置闪回。Wi-Fi 或 SIM 卡还在工作，真实位置从另一条通道漏出来了。

**Q：重启手机后失效了？**
Android 14 起的系统限制，重启后必须重新打开应用点一次「应用位置」。

**Q：某些应用能骗过，某些不行？**
做服务端交叉校验的应用骗不过。这是机制上限，不是配置问题。

**Q：需要 Root 吗？**
不需要。本工具只用 Android 官方提供的 Mock Location 调试能力。这也是它无法突破上面那些限制的原因——能力和限制是同一件事的两面。

**Q：会不会影响手机安全？**
应用只申请了定位相关权限和一个前台服务，没有网络权限，不会上传任何数据。所有坐标只存在本机 `SharedPreferences` 里。

## 技术原理

实现分三层：

```
MainActivity          UI、坐标输入、时间轴管理
      ↓
CoordinateConverter   GCJ-02 ⇄ WGS84 转换（纯 Java，可单测）
      ↓
MockLocationService   前台服务，独立线程每秒推送
      ↓
MockLocationEngine    addTestProvider + setTestProviderLocation
```

核心逻辑在 `MockLocationEngine`：

1. 用 `LocationManager.addTestProvider()` 注册三个与系统同名的测试 provider：`gps`、`network`、`fused`
2. 用 `ProviderProperties`（API 31+）或旧版重载声明每个 provider 的能力——GPS 支持海拔/速度/方向，network 不支持
3. 每 1000ms 构造一个 `Location` 对象，补齐精度、海拔、速度、方向、卫星数等字段，调用 `setTestProviderLocation()` 写入
4. 停止时 `setTestProviderEnabled(false)` + `removeTestProvider()`，系统自动回落到真实定位

几个实现上的坑，已经踩过并解决：

- **为什么用独立线程而不是 `Handler.postDelayed`**：在 ColorOS 16 上实测，应用退到后台约 5 秒后主线程延时消息会被挂起，定时器彻底停摆（进程没被冻结、前台服务也还在，就是不再调用 `setTestProviderLocation`）。改成 `Thread` + `sleep` 循环后不受消息队列调度策略影响
- **为什么必须接管 `fused`**：不接管的话，走 `FusedLocationProviderClient` 的应用拿到的永远是 `null`，只能退回自己缓存的位置
- **为什么三个源报不同精度**：Wi-Fi 定位的真实精度是 20~100 米，报 5 米在物理上不可能，定位 SDK 做合理性校验时很可能直接丢弃这种数据
- **为什么坐标转换只做一次**：转换结果随记录一起存下来，时间轴回放时直接用已转换的注入值，避免 GCJ-02 被反复反算导致漂移

## 项目结构

```
android-mock-tool/
├── app/src/main/
│   ├── java/com/example/mocktool/
│   │   ├── MainActivity.java           主界面
│   │   ├── MockLocationEngine.java     定位注入引擎（核心）
│   │   ├── MockLocationService.java    前台服务，持续推送
│   │   ├── CoordinateConverter.java    GCJ-02 ⇄ WGS84
│   │   ├── CoordinateValidator.java    输入校验
│   │   ├── PointStore.java             时间轴存储
│   │   └── SavedPoint.java             单条记录
│   ├── res/                            布局、图标、字符串
│   └── AndroidManifest.xml
├── app/src/test/java/.../              单元测试
└── apk/                                预编译 APK
```

单元测试覆盖坐标转换的双向一致性、境外不偏移、输入校验的边界情况：

```bash
./gradlew test
```
